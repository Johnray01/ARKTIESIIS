# Phase 13 — Testing Evidence and Objective Alignment

## Scope and evidence standard

This report compares the current application with the objectives as written in [docs/07-paper-objectives-scope-limitations.md](07-paper-objectives-scope-limitations.md). It does not change that source document or convert implementation clarifications into school policy. The objective descriptions below are concise paraphrases; the named source remains authoritative for the paper wording.

Automated route tests run against an ephemeral Express server and service/authentication test doubles unless stated otherwise. Unit and service tests use in-memory SQL harnesses and synthetic files. They are useful behavioral evidence, but they are not production tests or a manual UI review.

The database-administrator case could not be run against that environment because no credential was configured. To close the local role/access test gate without using live credentials, an explicit one-off HTTP matrix ran against a separate ephemeral Express app. It authenticated a mocked active `database_admin` actor and observed: `GET /admin` **200**, `GET /records` **200**, `GET /documents` **200**, `GET /finance` **200**, and `GET /dashboard/student` **403**. Read-service call assertions confirmed the permitted workspace summaries ran and the student's own-record/dashboard service methods were not called. Thus local HTTP role/access scenarios are exercised for all four roles; the configured live read-only matrix still covers only student, registrar, and finance. No account was created and no password was guessed. The manual browser walkthrough is deferred; those visual checks belong with Phase 14 UI review.

## Configured-environment workflow and limits

A **read-only local E2E smoke** passed against the configured local development SQL Server using the existing demo student credentials: password-only development login, database-backed dashboard dispatch/render, own document list, and a denied finance request. A further **16-case local role matrix** passed for the available student (6), registrar (6), and finance (4) accounts, covering the role-specific allowed and denied routes listed above. Neither run made persistent database or file changes. Both exercised the development-only password path, not email 2FA.

No document mutation or upload was run against the configured database. There is no isolated disposable SQL database/storage root for a live mutating test in this checkout; uploads, OCR jobs, audit entries, and immutable document revisions would persist in the configured development database/storage. No live OTP email was sent. As a result, the full email-2FA-to-persistent-upload/OCR/review/download workflow remains unverified end to end. Service tests, the synthetic-file native OCR integration, and the HTTP route tests with doubles provide the local evidence described above, but must not be represented as that live workflow.

## Phase 13 status

The Phase 13 applicable local automated and HTTP role/access gates pass: the configured local SQL-backed read-only matrix passed for student, registrar, and finance, and the mocked ephemeral HTTP matrix passed all five database-administrator cases above. No database-administrator credential is configured for the live local matrix, so **the live SQL-backed administrator check remains pending**. Full mutating authenticated E2E against an isolated disposable database and storage root, including live email 2FA, also remains pending; no such workflow is claimed as passed. The manual browser walkthrough is deferred to Phase 14. The objective gaps in Specific Objectives 2 and 4, the deletion difference in Specific Objective 3, and the unmeasured outcome in the general objective are documented evidence; this phase does not change or silently narrow the paper objectives.
